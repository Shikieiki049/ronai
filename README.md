# RON Strategist（RON 电脑玩家）

给 **Reign of Nether 1.5.1b**（Minecraft 1.20.1 + Forge 47.4.28）加电脑对手。
模组 id：`ronstrat`，产物：`build/libs/ron-strategist-1.0.0.jar`，需要和 RON 本体一起放进 `mods`。

## 怎么用

**选位界面（推荐）**：开房后进入 RON 的选位界面，每个空位的名字右侧有一个小按钮「电脑」。
点一下让电脑占这个位置，再点依次切换 简单 → 普通 → 困难 → 专家 → 取消。
电脑占位会自动算作“已准备”，所有位置准备好后照常倒计时开局，电脑和人类一样从该位置开局。
同一队伍颜色的玩家（包括电脑）自动结盟。只有房主 / OP 能设置电脑位。

**结盟 / 让分设置**：选位界面玩家列表右上角有「结盟/让分」按钮，点开后每个位置一行：
- 队伍：「按颜色」= RON 默认（同色结盟）；设成 队伍1~8 后，同一队伍开局结盟、不同队伍互为敌人（人类和电脑都适用）。
- 让分：每级 +2 村民、+0.5 倍初始资源，最多 4 级。开局约 2 秒后生效。只有房主 / OP 能修改，其他人只能查看。

**F7 面板**：游戏中按 F7，选难度和数量后添加对手；勾选“电脑之间结盟”并一次添加多个时，
你自动获得 1vN 让分（见下）。

**指令**（需要 OP）：
```
/ronstrat add <easy|normal|hard|expert> [x z]   在你的位置或指定坐标加一个电脑
/ronstrat ally <a> <b>                           让两个玩家结盟
/ronstrat handicap <玩家> <多出的敌人数>          给以少打多的一方让分
/ronstrat list                                   查看所有电脑的状态
/ronstrat arena <规格>                           原地生成测试场并开一局电脑对战，例：expert vs normal*5
```

## 难度

难度只改变决策质量，不改资源、不作弊（所有难度花一样的钱、遵守一样的科技树）。

| | 简单 | 普通 | 困难 | 专家 |
|---|---|---|---|---|
| 村民上限 | 9 | 13 | 18 | 55 |
| 常备军上限（人口） | 15 | 21 | 30 | 不限 |
| 反应间隔 | 3 秒 | 2 秒 | 1.25 秒 | 0.5 秒 |
| 首次进攻（±30% 随机） | 约 17 分钟 | 约 15 分钟 | 约 13 分钟 | 有优势就打 |
| 微操（集火 / 风筝 / 撤伤兵） | 无 | 无 | 集火 | 全部 |
| 箭塔驻防、市场交易、多城镇中心 | 无 | 无 | 部分 | 全部 |

**1vN 让分**：以少打多的一方，每多 1 个敌人，开局多 2 个村民、多 0.5 倍初始资源。

## 专家 AI 的思路（参考帝国时代2 社区强 AI）

- 经济：按需动态分配农民（相当于 AoE2 的 gatherer percentage，但随库存实时调整），
  先猎后农，远了就建仓库，多城镇中心爆农，研究背包，市场倒卖过剩资源。
- 建造：优先级 + 资源预留（escrow），永远不卡人口，保留通道不堵城镇中心。
- 军事：家门口防守用全军；有实力优势才出击；1vN 时趁对手还没成军逐个击破、留 1/3 守家；
  打不过就撤；铁傀儡吃矿不吃粮，用来绕开对手都在抢的粮食。
- 微操：远程集火、弩手风筝近战、贵重伤兵后撤。

参数都在 `config/ronstrat/params-<难度>.defaults.json`，复制成 `params-<难度>.json` 修改即可覆盖。

## 自动测试（开发用）

```
.\build.ps1 compileJava; .\build.ps1 dumpServerCmd
.\selfplay.ps1 -Spec "expert vs normal*5|expert vs hard*4" -Seeds 1,2,3 -Parallel 6 -Out results\x.jsonl -Map "<RON 地图存档路径>"
.\report.ps1 results\x.jsonl
.\tune.ps1 -Spec "expert vs normal*5" -Generations 5    # 自对弈参数搜索
```
无头服务器、可并行、自动加速；`-Map` 用真实 RON 地图的出生点，不加则生成平地测试场。

### 新版对旧版、测试套件、指标

- 冻结旧版：`py tools/freeze.py build204` 把这个标签的决策代码复制成第二个“大脑”（`src/baseline`，不进发布的 jar）。对局写法 `expert vs expert@base readied nohandicap`，同一局里新旧两版对打。
- 玩家写法：`难度[@大脑][:档案][:hN][*数量]`。档案是 `tuning/profiles/*.json` 里的一组参数覆盖（陪练打法 `rush7`、`push12`、`boom`）；`:h4` 是四级让分。
- 套件：`.\suite.ps1 -Suite duel -Label D205`（定义在 `tools/suites/`）。`duel` 新版对基线 60 局，是主指标；`spar` 对陪练打法；`handicap` 满让分 2v2，多张 4 人 / 6 人图；`team` 2v2 对基线；`regress` 对困难 AI 的老四项。输出胜率和 95% 置信区间，超时算半胜。`-Games 20` 先跑前 20 局做筛选。
- 指标：每局结果里带每个玩家的 `metrics`（`Telemetry.java`，从游戏本身读数，新旧大脑一视同仁）。`py tools/metrics.py results\D205.jsonl` 汇总成表：资源见底 / 堆积的时间占比、主城空转、村民和农田的时间点、第一个兵营和士兵、各时间点的兵力、盔甲和附魔覆盖率、同队到达敌方基地的时间差。
- 省时间的做法（不降低可靠性）：
  - 配对：同一张图、同一个种子换座位各打一局，两局合成一个观测值，出生位的好坏互相抵消。报告里的 `PAIRED` 一行是主要结论，另给出第 12 / 20 分钟的“实力占比”（村民 + 士兵 + 3 × 建筑），比胜负更灵敏。
  - 提前停止：配对结果已经分出“更好 / 没有更好”（序贯检验，48% 对 58%）就不再开新局；`-Full` 强制打完。
  - 提前判定：双方人数相等的对局，第 8 分钟后一方单位数是对方 2 倍、兵力不少于对方并保持 90 秒，就判胜（56 局镜像对局回查无一翻盘）；`-Extra "-Dronstrat.adjudicate=off"` 关闭。
  - 短局：`.\suite.ps1 -Suite econ -Label E205` 打 24 局 12 分钟的对局，比较双方第 5 / 10 / 12 分钟的村民、农田、建筑和采集量，改运营时先跑这个。
  - 没人用电脑时（10 分钟没有键鼠输入、RON 客户端没开）并发从 12 提到 16（`-ParallelIdle`）。
- 地图是官方地图包的副本，放在 `tmp\maps`（不入库）。
